# Native graph reconstruction: next concrete gate

## Current evidence boundary

`NATIVE-GRAPH.md` now checks substantial static descriptor construction, export routing and a conditional source assignment for the decoder. This is bounded static analysis of one pinned DLL build. It does not establish concrete runtime tensor handles/layouts or launch dataflow for the pre-decoder graph. The existing `native-chain-probe.py` executes a constructed native projection/repack chain with controlled activations and candidate weights; it is not the proprietary runtime's graph. Separately, `NATIVE-VENDOR-COMPARE.md` replays the decoder from captured vendor boundary buffers.

The raw reference planes in `REFERENCE-CAPTURE.md` and `NATIVE-INPUT-LAYOUT.md` are documented as packed input, but no checked operation maps them into the captured main/skip decoder windows. Temporal history enters before the decoder and the vendor-side recurrence is described in `TEMPORAL-HISTORY.md`; native recurrence therefore also depends on recovering/executing this missing pre-decoder path. No native live-input image result exists.

## Next bounded investigation

Do **not** launch another captured decoder comparison. The next high-value question is whether existing contained static/native artifacts can identify and validate the earliest runtime graph segment that consumes raw input planes and produces one of the decoder-boundary activation windows.

1. **Start with the available boundary captures, not another broad static inventory.** Local ignored `vr/logs/ladder/s0`, `s98` and `s99` captures include identical raw colour/depth/motion sidecar digests at 720×720, per-frame pool images and resource maps. The slot-99 boundary pmem changes from a 24-byte block at cut 98 to an 80-byte decoder block at cut 99 (`NVAPI-ARGS.md`, `NVAPI-BINDINGS.md`). Inspect the local trace files `vr/logs/capture/nvapi-trace-ladder-s0.log`, `nvapi-trace-ladder-s98.log` and `nvapi-trace-ladder-s99.log`, alongside each capture's `resource-map.txt` and three pool snapshots. These give concrete candidate raw-input regions and decoder input/output regions for a bounded binding audit.
2. Use the existing capture bytes to test one falsifiable connection: determine whether the raw planes are present in the captured pool at the relevant pre-block cut, then whether their ranges/identities enter the first kernel's inputs (slot 1 `cc_tinlayout_fused_pre_block_swin_1h_32_1_ds_fp8`) and are causally carried through to a specific decoder-boundary input window. Trace direction is not encoded by an alias alone; distinguish descriptor/resource identity from address reuse and keep read/write claims grounded in kernel evidence. The global layout sidecar omits several captured resources, so note gaps rather than extrapolating.
3. A useful validator should compare manifest and resource-map records against trace bindings and binary pool regions, assert address/range bounds, and detect ambiguities/aliases. Run it on independent cuts/runs and add synthetic corruption controls. Do not mutate or launch GPU probes until the static check identifies a specific missing fact they can resolve. Keep all tensor bytes and payloads local/ignored; report metadata and digests only.
4. If the available captures cannot link raw planes to slot 1 or onward, state exactly which binding/capture is absent and the smallest new controlled reference capture needed. Proton may supply that reference trace, but the final evaluator must not depend on it. No more input-layout scaffolding or synthetic replay without a falsifiable graph edge.

## Acceptance distinction

A bounded graph edge or replay would be intermediate evidence. End-to-end acceptance still requires raw/live input preprocessing, complete native graph execution and learned-weight bindings, native temporal state/reset recurrence, output conversion, and image comparison to repeated vendor references—all without Windows/DirectX/Proton in the evaluator.
